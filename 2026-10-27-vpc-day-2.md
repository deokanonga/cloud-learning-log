# VPC Day 2: Subnets in two Availability Zones

## What I built
- Created 4 subnets in deo-lab-vpc (10.0.0.0/16), Ohio (us-east-2)
- Gave each subnet its own /24 range inside the VPC
- Placed them in 2 Availability Zones: one public and one private subnet in each

| Subnet | AZ | CIDR |
|---|---|---|
| deo-lab-public-a | us-east-2a | 10.0.1.0/24 |
| deo-lab-public-b | us-east-2b | 10.0.2.0/24 |
| deo-lab-private-a | us-east-2a | 10.0.11.0/24 |
| deo-lab-private-b | us-east-2b | 10.0.12.0/24 |

## What I learned
- A subnet lives in exactly one Availability Zone and cannot span two
- Subnet ranges cannot overlap inside the same VPC
- An AZ can hold many subnets (up to 200 subnets per VPC)
- Subnet ranges are always private IPs, even in a "public" subnet
- A subnet becomes public when its route table has 0.0.0.0/0 -> Internet Gateway (the gateway attaches to the VPC, not the subnet)
- AWS reserves 5 IPs in every subnet (.0 network, .1 router, .2 DNS, .3 reserved, .255 broadcast), so a /24 has 251 usable
- Two AZs only give high availability if a copy of the app runs in each AZ, with a load balancer in front

## Subnet math
- Free bits = 32 - n (the slash number)
- Addresses = 2 to the power of the free bits
- Usable in AWS = addresses - 5
- Last address = start + size - 1
- Example: 10.0.1.0/27 -> 5 free bits -> 32 addresses (10.0.1.0 to 10.0.1.31) -> 27 usable; next range starts at 10.0.1.32
